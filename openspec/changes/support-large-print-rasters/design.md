# Design: 保留原始像素尺度的大圖檢測

## 現有行為

- 獨立印前檢測及網頁下單共用尺寸與 AI 轉外框檢查。訂單單筆和普通批量在基礎檢查後另做清晰度檢查，多圖簡易模式檢查 `.ai` 畫板數及轉外框。
- 點陣尺寸規則以原圖寬高換算比例，對比要求的毫米高度。這次沿用既有的比例、單位及取整規則。
- 清晰度以原圖像素的固定位置取塊，產出模糊面積及標記。現行位圖路徑先解碼整張、套用模糊遮罩與浮點混色，再縮小預覽。

## 實作決策

1. 從普通與多畫板分支移除 RGB 判斷並更新會員頁提示。刪除專用色彩模組前確認無其他呼叫者。
2. 在共用尺寸檢查使用經驗證的檔頭／解碼器中繼資料取得原始像素寬高。大圖保留獨立的檔案位元組、長寬、總像素及解碼預算限制。測試可從 3.5 億像素開始，正式值依壓測及主機資源確定。驗證格式與有效資料，訂單清晰度路徑須完整讀完檔案，截斷或解碼失敗回傳明確錯誤。
3. 優先評估維護中的順序解碼器。PNG 由上到下讀取原始像素列，按原演算法的網格及步長組成有限數量的列。對模糊遮罩的形態學閉運算，保留兩階段所需的上下邊界，跨帶合併區域，保留現行模糊面積、百分位選項、區域排序及原座標。分塊之前須核對解碼色值、位深、透明度及方向與原 OpenCV 路徑的對應。
4. 將原始座標及遮罩映射至小預覽後才產生標註；生產上傳使用原檔位元組。預覽邊界以輸出解析度呈現，模糊面積與通過／警告仍以原始像素尺度計算。
5. 以伺服器層的資源限額控制多個 Odoo 行程共用的大圖檢測容量。一般檔案保留原處理方式。大圖排隊超過等待時間或解碼失敗時回傳可重試或需修正的結果；既有模糊警告的確認上傳流程照常執行。
6. AI／PDF 的頁面讀取、AI 轉外框與嵌入圖 DPI 判定維持現有行為。AI 或 PDF 內嵌超大位圖的渲染記憶體需單獨量測。首階段將新增高像素位圖路徑限制於已實證解碼等價的格式。

## 驗證

- 附件 `布條_工作區域 1.png` 用 300 × 70 公分比對時，依現有取整規則得到 700 mm。用原始位元組回歸三個普通入口，確認普通訂單單筆及批量皆執行清晰度檢測。
- 比較同一原圖用舊版整圖運算與新版分塊運算的有效分塊、分數、模糊面積、排名與原座標。覆蓋跨越條帶的模糊區、最後不完整分塊及百分位模式。正式生產解碼器的驗證與本地順序掃描原型分開執行。
- 以清晰及模糊的 PNG、一般大小 JPEG／TIFF、單／多畫板 AI、PDF、錯誤比例、截斷檔及超預算輸入測試。針對多個客戶同時上傳測量峰值記憶體、延遲及排隊結果。
