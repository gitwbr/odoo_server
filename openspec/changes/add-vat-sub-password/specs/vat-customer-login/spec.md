## ADDED Requirements

### Requirement: 同一统编的主子密码
系统 SHALL 为每个统编账号支持一组主密码和至多一组子密码，保留原客户关联和现有主密码。

#### Scenario: 既有客户升级
- **WHEN** 通过 Odoo 模块升级新增字段
- **THEN** 原账号、主密码和客户资料保持不变
- **AND** 子密码默认为未设置，不能用于登录

#### Scenario: 后台设置或停用子密码
- **WHEN** 管理员在统编账号表单设置独立子密码
- **THEN** 系统以哈希保存子密码并显示已启用状态
- **AND** 管理员可重设或停用子密码
- **AND** 子密码不出现在搜索字符串或日志中

#### Scenario: 密码冲突
- **WHEN** 设置的主子密码相同或子密码等于统编
- **THEN** 系统拒绝保存并提示更换密码

### Requirement: 登录身份与业务权限
系统 SHALL 按密码确定主子身份，两种身份使用相同客户资料、共用 Odoo 用户及现有业务规则，不引入按主子划分的业务权限。

#### Scenario: 主子分别登录
- **WHEN** 客户在原登录页面提交同一统编与有效主密码或子密码
- **THEN** 会话保存相同 partner_id 及对应账号 ID
- **AND** 角色分别记录为 main 或 sub
- **AND** 两种身份的业务结果及权限范围一致
- **AND** 身份来自后端验证，不接受客户端指定角色

#### Scenario: 首次主账号登录
- **WHEN** 有效主密码仍为统编
- **THEN** 系统要求先修改主密码再登录

#### Scenario: 认证失败或登出
- **WHEN** 统编密码无效、共用 Odoo 用户认证失败或客户登出
- **THEN** 不留下本次登录的客户或主子身份

#### Scenario: 其他客户资料
- **WHEN** 主账号或子账号访问其他客户的订单或订单文件检查
- **THEN** 现有客户归属检查均拒绝该访问

### Requirement: 分别修改密码
系统 SHALL 验证旧密码以识别主子身份，并仅修改该身份对应的密码。

#### Scenario: 主子独立改密
- **WHEN** 客户提交有效旧密码和一致的新密码与确认密码
- **THEN** 系统只更新旧密码所对应的主密码或子密码
- **AND** 另一组密码保持有效

#### Scenario: 未设置主密码时验证旧密码
- **WHEN** 主密码字段为空且客户申请改密
- **THEN** 旧密码仍必须通过有效密码验证
- **AND** 任意非空旧密码不能绕过验证

#### Scenario: 错误或冲突的新密码
- **WHEN** 旧密码错误、新密码为空、确认密码不同或新密码与另一身份冲突
- **THEN** 系统拒绝修改，两组密码均保持不变
