- 2026-11-11：企业版测试库 `coinimaging` 已通过正常 `-u dtsc --stop-after-init --no-http --max-cron-threads=0` 升级，退出码 0。
- 使用现有 `odoo16e-runner` 镜像和企业版源码挂载；仅暂停、重启 `odoo16e-web`，未操作社区版服务。

- 未使用真实客户密码执行登录或改密；真实客户业务操作没有新增主子分权逻辑。

## 后台使用
1. 进入「印刷訂單系統 → 設置 → 統編帳號密碼」，打开客户账号。
2. 在「設定子密碼」输入子密码并保存；留空表示不变更。
3. 客户以相同统编和该子密码在 `/custom/login` 登录，页面显示「子帳號」。
4. 使用原主密码仍显示「主帳號」。两种身份绑定同一客户，业务操作规则一致。
5. 修改密码时填入对应的旧密码，系统只更新该组密码；后台也可重设子密码。
6. 「停用子帳號」清除子密码，阻止之后使用该密码登录。与现有主密码机制一致，此按钮不强制撤销已登录的浏览器会话。

会话字段：`partner_id` 为所属客户，`vat_login_id` 为统编账号记录，`vat_login_role` 为 `main` 或 `sub`。未来权限需求应从已验证的会话身份读取，不接受客户端提交的角色。

## 正式环境
正式环境在另一台服务器，本次未部署。部署企业版 `dtsc` 修改后，在其原虚拟环境内停止现有 Web 进程，以正式库名正常升级模块：

```bash
python3 ./odooE/odoo-bin -c /home/bryant/odooE/config/odoo.conf -d <正式資料庫名稱> -u dtsc --stop-after-init --no-http --max-cron-threads=0
```

升级成功后按既有 `nohup` 方式启动。不能只重启而跳过模块升级，否则新增字段和后台视图不会就绪。
