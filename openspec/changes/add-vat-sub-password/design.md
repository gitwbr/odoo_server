## Context
现有 `dtsc.vatlogin` 每个统编唯一，绑定 `res.partner`。登录验证后认证共用 Odoo 用户，并将客户 ID 保存在 `session['partner_id']`。查单、客户报价和文件检测沿用该客户身份。

## Decisions
- 扩展原模型，在同一记录保存子密码哈希；后台以只写密码字段设置，提供启用状态和停用按钮。沿用 Odoo 的密码哈希工具，不记录或展示子密码明文。
- 主密码格式保持兼容；有效主密码仍为 `vat_password or vat`。子密码不得等于有效主密码或统编，避免身份歧义和公开默认密码。
- 会话新增 `vat_login_id`、`vat_login_role`，仅在两层认证成功后写入。切换登录和登出清除旧身份；原会话没有角色字段时按历史主账号解释。
- `partner_id`、认证的 Odoo 用户、业务域和 ACL 均不随角色改变。主子标记仅供显示和后续功能使用。
- 登录页面无需选择身份。改密页面按提交的旧密码识别主子，只改对应密码；错误旧密码、空密码和密码碰撞均拒绝。
- 保留首次主账号使用统编时必须改密的行为。新子账号不沿用统编作为默认密码。
- 登录和改密表单使用 Odoo CSRF token。失败认证不得留下新的客户身份。

## Migration and deployment
- 不运行 SQL、数据回填或批量密码修改。新增存储字段由 Odoo `-u dtsc` 创建，现有记录默认为未启用子密码。
- 管理员通过「統編帳號密碼」表单设置子密码；无需直接进入数据库。
- 当前服务器仅为企业版测试环境。正式环境需部署代码并按原运行方式正常升级模块。

## Validation
- 在不连接业务数据库的测试中验证密码匹配、哈希、冲突、首次改密、主子分别改密、失败认证、切换与登出。
- 比较两种登录的客户 ID、Odoo 用户和业务查询结果；验证其他客户订单及文件检查仍被拒绝。
- 校验 Python/XML 和 OpenSpec；能访问测试运行环境时，通过正常 Odoo 加载/升级验证字段与视图。
