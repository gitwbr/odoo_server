# Change: 扩大企业版 AI 助手业务查询与关联分析能力

## Why

现有助手已具有模型发现、字段说明、明细查询、聚合、Many2one 去重五种操作，查询范围由印刷系统菜单入口、直接业务关系与当前用户权限动态决定。但只支持 AND 条件、一层 Many2one 路径、单模型统计和最多 100 条明细，无法稳定回答完整订单链路、缺失单据、跨模型母单去重、下一页与复杂报表问题。

目标是扩大员工实际能问的问题，而不只是增加技术模型数量。本提案只规划后续能力；前序权限与结果展示修复不重复纳入。本文记录的是本机源码能力，不代表正式环境已部署或完成真实问答验收。

## 当前能力盘点

以下为源码菜单与关系可达的候选范围，实际以运行环境安装状态、动态目录及当前账号权限为准。

| 业务范围 | 当前可尝试的问题 | 重要边界 |
| --- | --- | --- |
| 大图订单 A/F/E/M/D、产品行 | 指定单号、客户/案名/日期/状态筛选；按月、客户、类型统计 | F 是打样；M 是被合并的非目标订单；不能把任意金额字段都称为营业额 |
| B 内部、C 委外、G 代工、T 施工工单及明细 | 工单列表、状态、单模型数量、按 checkout_id 去重母单数量 | B/G 需求允许重叠；跨模型母单联集尚不支持精确通用计算 |
| S 出货单及明细 | 出货日期、状态、客户、单号；单模型分组统计 | checkout_ids 为多对多，完整母单展开受限；排定发货不等于实际已出货 |
| 客户、供应商 | 名称、分类及可读资料筛选；按客户查询相关订单 | 联系人关系等是否可达由目录决定 |
| 产品、属性、分类、供应商价格 | 产品资料、分类、属性价格、供应商价格记录 | 不默认读取图像、附件等大字段 |
| 采购 | 采购单头、供应商、状态、存储金额字段统计 | 标准 purchase.order.line 不会因关联自动纳入，完整采购明细需补范围 |
| 库存 | quant、批次、调拨、移动行、补货规则；自定义扣料记录 | 当前库存、可用量、预测量、库存估值不能混称；报表计算不自动继承 |
| 应收应付、发票、折让、零用金 | 账单头、状态、金额等已存字段；发票和折让及自定义明细 | account.move.line、核销明细、完整账龄与特定财务报表需补能力和口径 |
| 人员、工时、考勤、请假、薪资 | 有权限的原始记录、存储字段筛选/统计 | 不把原始记录统计等同于薪资计算或绩效报表；人事权限沿用系统 |
| 资产与使用记录 | 资产分类、借用/使用记录、时间筛选 | “利用率”等指标需要先定义可用时间和使用时长口径 |
| 机台、后加工、材料与基础配置 | 已纳入目录的机台/后加工/材料记录及生产行统计 | 非存储计算字段不能直接聚合 |
| 上传通知及业务备注记录 | 菜单或一层关系可达的通知、备注记录 | 不代表能读取上传文件内容、PDF 或图片 |

共同限制：明细默认 20/最大 100；分组默认 20/最大 100；最多 20 个返回字段、20 个 AND 条件、3 个分组字段、5 个聚合指标。日期支持日/周/月/季/年。标准 CRM 商机、销售报价、付款核销和其他应用模型不能仅凭已安装就承诺开放。Server Action 只贡献声明绑定模型，不执行其报表代码。

## What Changes

### 第一阶段：查询范围透明、查询能继续

- 在助手中提供“我能查什么”，按当前账号动态列出业务类别、可用操作和示例；新菜单与合格业务关系自动反映在目录中。
- 增加带稳定排序的分页，支持“下一页”“继续列出”，保留模型、条件、字段及顺序，明确总数与截断信息。
- 支持受限 AND/OR/NOT 组合，仍使用结构化参数并限制深度、条件数与查询成本。
- 补充已开放业务的标准明细模型范围：优先采购行、账单行、销售单/报价及明细、库存移动、付款核销。按业务应用与关系来源分组声明资格，不开放整个 registry。
- 为重复名称返回候选项；对最近结果中的“第 N 笔”按稳定结果引用定位，而不依赖 LLM 猜测。

### 第二阶段：订单全链路与缺失关系

- 增加可复用的关联查询操作，支持父子明细、Many2many 关联列表、存在/不存在关联过滤；每一步保留权限和返回上限。
- 首批链路：checkout → 产品行 → B/C/G/T → S；采购 → 收货；账单 → 发票/折让/核销（按实际关系逐条验收）。
- 增加跨模型集合并集/交集/差集计数，例如 B/G 母单去重总数、未生成有效 S 的订单。
- 支持“当前流程状态与缺失环节”，只报告记录中可证实的状态，不将推测原因作为事实。

### 第三阶段：统一业务指标

- 为逾期、未出货、未完工、未收款、重制率、完成率、工时等建立小型版本化指标定义；注明日期字段、有效状态、金额税别、币种和计数对象。
- 相对日期固定使用当前用户时区；对同比、环比、同天数比较提供确定性计算；缺失月份补零必须标注。
- 必须分别定义“大图订单逾期”和“S 出货单逾期”；区分工单需求数、实际生成数和母单去重数。
- 毛利、账龄、利用率、材料损耗等先确认分子/分母、成本与时间来源，不能只由提示词推导。
- 把现有报表的纯读取计算提取为可复用服务；禁止直接执行可能写入的按钮/Server Action 来取数。

### 第四阶段：常用问题与结果交付

- 提供老板/业务/生产/采购/财务的常用查询模板，仍用通用查询底座执行。
- 回答附查询条件、时间范围、统计口径和可打开的原始单据；明细、趋势与排行使用合适的表格/图表。
- 受限 CSV/XLSX 导出：复用原查询与权限，显式标明完整或部分，不把截断列表导出成“全部”。
- 收藏问题、命名会话、重新执行查询属于可选持久化能力，实施前单独确认存储方式；本次不写数据库配置。

### 第五阶段：文件知识检索（独立后续范围）

- 若确有需求，再接入有权限的 SOP、报价规则、产品说明及订单附件文本检索。
- PDF 文本、OCR、图片内容和业务数据库查询分开验收，回答引用具体文档页码/段落及版本。
- 不把文件检索当作当前已具备的能力；需要额外的索引、附件权限和文档更新机制。

## 具体问法与验收方向

1. 查 A/F/E/M/D 指定订单和全部产品明细，跳转正确。
2. 查某客户本月订单，按明确金额口径排名；跨币种不直接相加。
3. 今天应处理的 B/C/G/T 工单分别有哪些，哪些关联同一母单。
4. 一张订单有哪些工单、哪些已完成、哪些尚未生成。
5. 哪些母单还没有有效 S；作废 S 不算有效出货。
6. 一张 S 包含哪些母单，每张母单的状态是什么。
7. B/G 合计涉及多少张不重复母单；大于明细分页上限仍必须精确计数。
8. 某原料当前库存、所在仓库/批次，以及最近扣料记录。
9. 哪些采购单尚有未收数量，展开相应采购行与收货记录。
10. 某客户有哪些未结清账单和发票/折让，账龄按确认口径计算。
11. 某员工本月工时、关联工单及考勤异常原始记录。
12. 某资产最近使用情况；利用率只在口径定义后开放。
13. 同比/环比列出两个期间原值、变化额与变化率；分母为零时不伪造百分比。
14. 显示第 101–120 条，继续后不重复、不漏行；数据变动导致分页变化时提示。
15. “内部工单或委外工单，且未完成”正确编译组合条件。

## Impact

- Affected specs: `odoo-ai-assistant`
- Affected code: `dtsc_ai_assistant`、`dtsc_ai_gateway`、独立 Gateway；必要时提取 `dtsc` 的纯读取报表服务。
- 先完成第一、二阶段，可明显扩大查询问题覆盖；第三阶段提高统计一致性，第四阶段改善日常使用，第五阶段另行立项。
- 本次交付为待审阅方案，不实施新增能力，不修改数据库资料，不部署正式环境。
- 待明确事项：优先业务岗位；“我的订单”的归属定义；逾期完成/出货时间；金额税别币种；是否需要持久收藏、文件检索。
